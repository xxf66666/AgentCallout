# AgentCallout v0.3.0

2026-09-13。可选本地中英文 OCR 定位版本，功能提交 `d338dc8`，跨平台测试修复 `17cb5c7`。

## 本版功能

- 可选本地 OCR locator（Tesseract.js 7，固定 `eng` + `chi_sim` 模型）。默认安装不下载引擎或模型，由 `agent-callout ocr install/status` 显式管理；识别在隔离子进程离线执行，禁止网络与子进程创建。
- CLI `locate-text` 与 MCP `locate_text`：exact/contains 匹配、大小写不敏感、NFKC 与统一空白、去除相邻 CJK 字符间 OCR 插入空格；多候选、置信度与 word/symbol 精度证据。
- ROI 裁剪、1–4 倍整数缩放与反色预处理；EXIF 定向、透明背景合成白色；处理像素上限 1,000 万，超限显式报错。
- 候选绑定输入 SHA-256 与处理证据（引擎、模型版本/hash、变换链）；识别期间输入变化返回 `OCR_INPUT_CHANGED`，失败不返回伪造候选。
- 多候选或低置信度返回 `requiresConfirmation` 与原因列表，无自动选坐标路径；`not-found` 不表示文字一定不存在。
- OCR 只输出文字候选 bbox；批注继续由现有 AnnotationSpec 渲染器完成。

## 跨平台测试修复（`17cb5c7`）

- 测试临时目录统一经 `realpath` 规范化，匹配产品对输入/输出的符号链接解析路径（macOS `/var` → `/private/var`）；Windows 上为恒等变换。
- 删除一条仅在 Windows 上因 JSON 反斜杠转义才成立的断言（文本回退响应契约本身包含 `outputPath`）；保留真正有意义的保护：无图片内容、无 `pixelMetrics`。
- 文字度量金标准沿用既有 `verifiedWindowsRenderer` 先例：win32 精确锁定，其他平台断言确定性布局（文字框起点、编号 marker、目标/锚点关系）并给文字度量尺寸 ±4 px 容差。跨平台 pango 文字度量差异（多词中英混排约 3 px）是文档化的平台行为，不是渲染回归；同平台重放 `outputSha256` 仍然逐字节一致。

## 已知边界与后续

- OCR 置信度是引擎原始分，**不跨平台可比**：同一反白按钮 Windows 原型约 96 分，macOS 正式运行时 38–48 分，两边坐标同样正确；确认决策以运行时阈值与 `requiresConfirmation` 为准。
- 本版发布级验收平台为 macOS（客户端闭环）与 Windows（开发测试）；Linux、Node 20/22 回归与三平台 CI 矩阵属 0.4.x。
- 示例 PNG 基线仍由 Windows 渲染；macOS 重新生成会因文字度量差异产生不同字节（已文档化），本版未重生示例。
- 下一阶段：0.3.1 一键交接包、0.4.0 浏览器 DOM 定位、0.4.x 协作与平台完善，见[路线图](../roadmap.md)。
